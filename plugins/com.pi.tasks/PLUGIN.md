# 日程本

用户的计划表，外加**每天一页的记录**。**待办、日程、定时任务是同一种东西**，区别只在于：没有时间的是待办，有时间的是日程，有时间加重复加触发的就是定时任务。

每条事项和每段日记都**归属一个工作区**，或者属于「全局」（不属于任何项目的那一类，比如交房租）。默认落在调用你的那个会话所在的工作区，所以同一个「站会」在两个项目里是两条互不相干的事项。

## 六个工具

### `item_add({ title, when?, end?, note?, repeat?, remindBefore?, onDue?, scope? })`

记一条。`title` 必填；给了 `when` 才有时间，否则是一条纯待办。归属默认是当前工作区；只有用户明确说这件事不属于任何项目时，才传 `scope: 'global'`。

**`when` 优先用明确写法**（`2026-09-30 14:00`、`2026-09-30`）。也认自由文本（`明天下午3点`、`后天`、`下周五`、`下个月1号`），但那是有损的：**解析结果会原样回给你**，如果读错了用户会看见。

> `后天` 和 `大后天` 这类词标准的解析库其实读不出来，是这里补上的。但 `下周`、`周末` 这种没有具体日子的说法**会被拒绝**——宁可问清楚，也不猜一个日期存下去。

- `repeat`：`daily` / `weekly` / `monthly` / `yearly`，或直接给 RRULE，例如 `FREQ=MONTHLY;BYDAY=-1FR`（每月最后一个周五）。**必须同时给 `when`。**
- `remindBefore`：提前多少**分钟**发系统通知，例如 `15`。
- `onDue`：到点发给**你**（agent）的一句话，例如「总结昨天的提交」。这是让 agent 定时干活的入口。

### `item_list({ range?, scope? })`

`today` / `week`（默认）/ `all`。列出时间、重复规则、完成状态、**下次触发时间**。

### `item_update({ title, when?, note?, repeat?, done?, scope? })`

改一条。按**标题包含**找，只改你传的字段。`when` 传空字符串表示去掉时间。

### `item_remove({ title, scope? })`

删一条。除非用户明说删，否则优先用 `item_update({ done: true })`。

## 每天一页（回顾）

面板上「回顾」那个页签，是**一天一页**：

- **上半页自动的**——那天计划了什么、真完成了什么、哪个触发错过了
- **下半页是用户自己写的**——一段自由文字

### `day_read({ day?, from?, to?, scope? })`

读某一天（或一段日期）发生了什么：完成了什么、计划了没做什么、错过了哪些触发、用户自己写了什么。

**写总结之前先读这个。** 用户问「我上周干了什么」「我之前写过什么」也用它。一次最多读 90 天。

### `day_write({ day?, text, mode?, scope? })`

写用户那一天的记录（就是下半页那段文字）。

**默认是追加（append），不是覆盖**——用户自己写的话不能被冲掉。只有用户明确说「重写这一天」时才用 `mode: 'replace'`。

**这是最值得主动用的一个工具。** 用户说「把今天整理一下」「总结一下这周」的时候，你整场对话都在场，知道发生了什么：先 `day_read` 拿到那天的完成/错过，再把你看到的东西写成两三句话 `day_write` 进去。

但**不要**每天都自动写——用户没让写就别写，那是他的日记。

> 用户自己写的内容**永远不会**被自动塞进上下文（和知识库相反）。要看得主动 `day_read`。

## 工作区归属

每条事项和每段日记都挂在**一个工作区**下，或者属于**全局**（不属于任何项目）。读和写默认都只作用于「当前工作区 + 全局」：

- **写**（`item_add` / `day_write`）默认落在当前会话所在的工作区；`scope: 'global'` 才落全局。
- **读和改**（`item_list` / `item_update` / `item_remove` / `day_read`）默认只看当前工作区 + 全局，避免在项目 B 里改到项目 A 的同名事项。要看全部，传 `scope: 'all'`，并在回答里说清楚是谁的。
- 返回的文字里每条都标了归属（`·[项目名]` / `·[全局]`）。

如果宿主没有告诉本次调用属于哪个工作区（极少见），一切按**全局**处理——宁可放在「不属于任何项目」，也不猜一个放进去。

## 匹配规则（和旧版「待办」一致）

`item_update` / `item_remove` 按**标题包含**匹配（`title.includes(...)`），不是精确相等；搜索范围先按上面的工作区规则收窄。命中多条时取**最近创建的那条**。找不到会报错——报错说明标题打错了，或者它在别的工作区（试试 `scope: 'all'`）。

## 完成是按「每一次」算的

「每周一 9 点的站会」标完成，**只标掉这一次**，下周一的还在。所以同一个标题的重复事项，这周做完了下周还是未完成，这是对的。

## 什么时候用

- 用户明确要求记住 / 提醒 / 安排某件事
- 用户提到具体的会议、截止时间、约会
- 用户问「我今天有什么事」「这周安排」
- 一件事需要拆成多步跟踪

## 边界（不要向用户承诺这些）

- **不会在应用关闭时触发。** 这是桌面应用，不是系统闹钟。应用没开时到点的触发会被记成「错过」，下次打开时列出来，**由用户决定要不要补跑**——不会自动补，也不会悄悄丢掉。
- **「让 agent 干活」需要应用窗口开着。** 到点时如果窗口没开，这次会记成「没送到」，同样是等用户决定。
- **不连外部日历。** 不读也不写系统日历、Google Calendar、CalDAV。
- 到点发的是**应用内 + 系统通知**，不是短信或邮件。
- **日记内容不会自动出现在你的上下文里。** 需要的时候用 `day_read` 去读，不要假装自己记得用户写过什么——没读过就是没读过。
- 无时间的待办不出现在任何一天的「那天」里（它没有日期可放），但**完成的那天会出现在「完成」里**。
