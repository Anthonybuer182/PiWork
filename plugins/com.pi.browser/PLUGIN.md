# 浏览器自动化

宿主内嵌了一个浏览器，你操作的就是它。本插件的面板「浏览器」就是那块显示页面的区域：
一条工具栏（后退 / 前进 / 刷新 / 地址栏）加标签页。你开页面、读页面、点按钮、填表单，
用户在面板里看到的一直是你操作的这个页面。

## 标准操作循环

```
browser_navigate → browser_get_state → browser_click / browser_fill → browser_get_state 验证
```

`browser_get_state` 返回页面**可交互元素快照**（按钮 / 链接 / 输入框，各带一个 ref）。
操作优先用快照里的 ref（如 `"[12]"`），找不到再用文字或 CSS。

## 工具一览

| 工具 | 干什么 |
|---|---|
| `browser_navigate({ url })` | 打开网址并等加载完，返回最终地址和标题。没写协议自动补 `https://` |
| `browser_get_state()` | 当前地址、标题 + 可交互元素快照（ref 可直接当选择器用） |
| `browser_find({ query })` | 按文字模糊找元素（带匹配度和分区），快照被截断或要精确定位时用 |
| `browser_click({ selector })` | 点击。等元素出现（最多 5s）、滚到可见再点；失败时会给出相似元素建议 |
| `browser_fill({ selector, value })` | 填输入框（替换现有内容），对 React/Vue 受控组件有效 |
| `browser_upload({ selector, files })` | 给上传控件塞本地文件：点「添加附件 / 上传 / 选择文件」，浏览器会报出页面真正要的那个文件框（隐藏的、临时创建的、在 iframe 里的都行）。`files` 传绝对路径。**不要用 `browser_fill` 填文件框**，它塞不进路径 |
| `browser_act({ steps })` | 一次做几步，按顺序执行：`click` / `fill` / `select` / `upload` / `hover` / `wait`。某步失败就停，返回每步结果 + 执行完的页面快照。适合**已经看得见**的连续动作（填完表单再提交）；下一步的落点要等上一步才出现时（比如点了「回复」才弹出的输入框），先单独点、看清了再批量 |
| `browser_hover({ selector })` | 悬停——只展开 hover 菜单 / 气泡提示用 |
| `browser_select({ selector, value })` | 下拉框按 value 或可见文本选中 |
| `browser_scroll({ direction?, amount? })` | 上下滚动，默认向下 500px |
| `browser_evaluate({ expression })` | 在页面上下文执行 JS 并返回结果。读快照表达不了的**计算出来的**数据时用 |
| `browser_walk({ goal, maxSteps? })` | 按目标自动导航（如「进入个人设置页」）：自己看截图规划点击路径并执行。需要配置了视觉模型；失败时退化为关键词匹配 |
| `browser_screenshot({ fullPage? })` | 截图，返回真正的 PNG 图片 |
| `browser_history_search({ query?, limit? })` | 搜浏览历史（标题 + 网址，按词匹配、每个词都要命中）。用户说「上次那个网站」时先查这里，别让他重打一遍网址 |
| `browser_favorites_list()` | 列出用户收藏的网站。用户说「我常用的那个」时用它换成真实网址 |
| `browser_show({ text, title?, kind? })` | 把内容展示在浏览器的划词卡片上（见下节：这是用户要看的**唯一**出口） |
| `browser_clips_list({ query? })` | 列出用户划词收藏的文字片段。他说「我收藏的那段话」时用它 |

## 划词复合框（重要）

用户在网页里选中文字时，选区下方弹出一个复合框：上面一行是「翻译 / 解释 / 朗读 / 收藏」，下面是一个
**引用标签**（显示选中的那段文字，可点 ✕ 拆掉）加一个**问题输入框**，再下面是结果区。

- 点**翻译 / 解释** → 翻译/解释的是**引用标签里那段原文**（标签拆了这两个钮就不可用），并明确要求
  调用 `browser_show` 展示结果。你在这种请求里**必须用 `browser_show` 回答**，把完整译文/解释放进
  `text`，`kind` 填 `translate` / `explain`。**不要只写在对话回复里** —— 结果会显示在他眼前的框内，
  写到对话里他看不到。
- 在问题框里按**回车**（或点发送）→ 消息 = **他打的问题 + 「引用」原文**（只发引用、只发问题都可以）。
  这种消息会明确要求你调用 `browser_show` 把**简明回答**展示到弹框（kind 填 `chat`、title 填 `回答`）——
  照做：他在看着框，等的是框里的那句话。对话里正常完整作答，两边内容不要互相重复。
- 点**朗读** → 用客户端的语音合成朗读引用标签里的**选中文字**（再点一次停止）。这走宿主的
  `voice.speak` 能力，需要 manifest 里的 `voice` 权限；语音未配置时框内会提示原因。
- 翻译 / 解释完成后，**结果卡片标题右侧有一个扬声器图标**，点它朗读的是译文/解释本身
  （而不是原文），再点一次停止；右下角兜底卡片同样带这个图标。
- 点**收藏** → 引用那段文字进插件自己的片段库，框内会列出最近收藏（可逐条删除）。
  他问「我收藏的那段话」时用 `browser_clips_list` 找回来。
- 框一旦被操作过（点了按钮或光标进了输入框）就**钉住**，随便点别处不会消失；点 × 或按 Esc 才关。

`browser_show` 不止给划词用：任何「展示在浏览器里给用户看」的内容都可以走它；框不在了它会落到
右下角的小卡片上。

## 整页翻译 / 朗读 / 解释 / 收藏

工具栏的「译」是整页功能的开关：点开后在工具栏下方展开一行控制条，再点一次收起
（收起不改变页面）。所有操作都在这一行里完成，不会盖住网页内容。

| 动作 | 行为 |
|---|---|
| 翻译（替换原文） | Google 式：原文位置直接换成译文 |
| 双语（保留原文） | 沉浸式：译文追加在原文下方；按钮、导航等行内组件并排显示 |
| 原文 | 还原页面 |
| 朗读 | 按当前显示层朗读：双语读原文+译文，替换读译文。行上有暂停 / 上一段 / 下一段 / 停止 |
| 解释 | 提取正文，给出主旨、要点、术语，在页面右侧抽屉显示 |
| 收藏 | 页面级收藏，原文和译文一起存；`browser_clips_list` 里显示为「[整页] 标题」 |

行为约定：

- 打开页面不会自动翻译，只有点「翻译 / 双语」才会开始。
- 状态跟着标签页走：每个页面各自独立；分屏时控制条显示当前聚焦那一栏的状态。
- 译文按「站点 + 原文哈希」缓存，同一页重访不重复调用模型。
- 跨域 iframe、closed shadow DOM 里的文字翻不了；控制条会提示「含内嵌框架」。
- 某段失败时原文会出现红色虚线下划线，控制条出现「重试 n」。

权限：manifest 里的 `ai`。翻译和解释都走宿主的 `ai.complete`（用户设置的默认对话
模型），会消耗该模型的 token；整页翻译按批发送，长页面在开始前会显示段数。

## 历史与收藏

面板地址栏带一套收藏 / 历史：星标收藏、访问自动记录（含标题），点地址栏就出下拉直达。
数据在插件自己的存储里，和宿主无关。

- **历史**：每次导航自动记一条，按网址去重（同一页 `#锚点` 跳转不算新访问），保留最近 500 条。
  面板里有「不记历史」开关，用户开了之后不再记录——**这不影响你**，你照样能正常导航；
  它只管历史，不影响登录状态和 cookie；
  但那段时间的页面不会出现在 `browser_history_search` 里，查不到就直说。
  用户也可以一键清空历史（收藏不受影响）。
- **收藏**：用户手动星标的，数量少、是「他想快速回到的地方」。**收藏是用户的动作**——
  不要替他收藏，也不要把浏览历史当成收藏来报。

## 快捷配方（记录下来的操作）

用户**收藏**过的站点上，一次成功的 `browser_act` 会自动记成「配方」：步骤、每步的目标
（带备选定位，站点小改也能点到）、每步当时页面发生了什么。之后 `browser_navigate` 的
返回里会提到本站有什么配方，用 `browser_recipes` 看步骤，再按 `browser_act` 执行：

```
browser_recipes({ origin: "bilibili.com" })
browser_act({ recipe: "搜索并播放", steps: [ ...把 {{n}} 换成这次的值... ] })
```

- `recipe` 填了名字，**目标和备选定位以配方为准**，你只负责给值——别把它简化成第一个候选。
- 某一步「预期」对不上就停下自己操作，不要硬着头皮往下点。
- 配方里 `[已失效]` = 连着失败两次，已经不再出现在导航提示里。它下面会写**上次失败在第几步、
  为什么**：能绕开就绕开那一步自己操作；修选择器是用户的活（面板地址栏下拉里点 ✎ 就能改，
  ▶ 可以当场试运行）。
- 配方只在收藏的站点上自动记录——收藏是用户的动作，不要替他收藏来「开启记录」。

## 选择器格式

`browser_click` / `browser_fill` / `browser_hover` / `browser_select` 共用一套：

- `[12]` —— 快照 / `browser_find` 给出的 ref（**首选**）
- `text="登录"` —— 按可见文字
- `role=button[name="提交"]` —— 按 ARIA 角色
- 标准 CSS —— 最后手段，站点改版就失效

## 看页面内容的两条路

1. **`browser_get_state`** —— 要"页面上有什么、能点什么"就用它，文字快照，便宜
2. **`browser_screenshot`** —— 要看排版、图表、图片、验证码这类**视觉**信息才用；
   截图占上下文，别没事整页截。页面很长就配合 `browser_scroll` 分段看

## 边界

- 页面在**内嵌的浏览器**里打开，不是系统浏览器。整个应用只有一个浏览器，
  你打开的和用户在「浏览器」面板里看到的是**同一个页面**——你导航，用户那边跟着变；反过来也一样。
  切走面板再回来，页面还在（浏览器本身一直活着）。
- 有些站点会检测自动化环境或需要登录，可能打不开或显示不全；截出来什么样就说什么，别猜。
- `browser_evaluate` 是页面里的明牌 JS，站点看得见。**不要用它绕过站点的反自动化措施**——
  绕不过去就如实告诉用户。
- `browser_walk` 依赖视觉模型配置；没配会直接报错，退回 `get_state → find → click` 手动走。

## 宿主语音能力（voice）

插件后端可通过 `ctx.call` 调用宿主朗读能力（需要 manifest 声明 `permissions: ["voice"]`）：

| 方法 | 参数 | 作用 |
|---|---|---|
| `voice.speak` | `{ text, toggle? }` | 朗读文本（最长 8000 字）。`toggle: true`（默认）时，若本插件正在朗读则停止；否则开始 |
| `voice.stop` | — | 停止本插件的朗读 |

音频由宿主渲染进程播放，插件拿不到音频数据；朗读使用用户在「设置 → 语音」中选择的 TTS 供应商。
同一时间只有一个播放器：插件朗读会停止对话里的朗读，反之亦然。
